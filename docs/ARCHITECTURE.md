# Architecture

## High-level flow

```
[User] --PTT--> [Atomic Echo Mic]
                    |
                    v
              [16 kHz PCM]
                    |
         +----------+----------+
         |                     |
    Groq Whisper STT      (optional local VAD)
         |                     |
         v                     v
   [transcript] --------> [LLM client]
                              |
              +---------------+---------------+
              |               |               |
           Groq API      On-device eng.   Weight stream
              |               |               |
              +-------+-------+-------+-------+
                      |
                 [reply text]
                      |
              +-------+-------+
              |               |
         Edge TTS / Groq   On-device beep
              |               |
              v               v
         [PCM play] ----> [Speaker]
                      |
                 lip-sync amplitude
                      |
                 [Fox avatar]
```

## Controls
- IMU flick up/down → menu navigation
- Button single click → confirm
- Double click → open menu
- Long press → PTT

## Tools exposed to the LLM
- `ble_radar` — BLE scan + IMU orientation → polar list
- `wifi_scan` — AP list
- `ir_send` — raw / learned codes
- `imu_gesture` — current gesture

Menu can run the same tools without the LLM; the fox “does the work” then steps aside for the radar/plot UI.

## Persistence
- NVS only (fox name, API key, mode, tiny context summary)
- Never store full conversation history on flash

## Build path
Web UI → config JSON → GitHub Actions (ESP-IDF) → merged `.bin` → ESP Web Tools / esptool-js in the browser.

## Clever-hack modules (added)

- **Bayesian 20 Questions (`fox_bayes.inc`).** Keeps a probability distribution
  over candidate entities and applies Bayes' rule after each yes/no. Picks the
  question with maximum expected information gain (entropy reduction) each turn,
  so it converges in ~5 questions and tolerates the occasional wrong answer.
  Verified: 10/10 with honest answers, ~93% under 10% answer noise.

- **Markov chatter (`fox_markov.inc`).** Idle mutterings are generated by walking
  a per-mood word Markov chain seeded from a compact corpus, so the fox varies
  its spontaneous lines instead of repeating fixed strings.

- **Pwnagotchi-style RF mood (`fox_markov.inc`).** A self-throttled background
  sampler counts nearby WiFi APs and nudges the fox's needs: a surge of new
  signals excites it and increments a lifetime "friends met" counter; empty air
  makes it wistful. The radios literally colour the personality.

- **LLM tool-calling (`fox_main.cpp`).** In cloud mode the fox advertises its
  tools (BLE/WiFi scan, space weather, weather, TV power) as OpenAI-style
  function tools, runs any the model requests, feeds results back, and speaks the
  final reply — the on-device tools become things the conversation can invoke.
